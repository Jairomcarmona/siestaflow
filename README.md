# SIESTAFLOW

SIESTAFLOW 0.2 is a declarative, evidence-oriented orchestrator for SIESTA
campaigns in persistent SLURM allocations. It prepares self-contained packages
locally; the user transfers and submits them manually. The controller itself
lives only inside the allocation.

Current engineering state: `V0_2_CONSOLIDATION_ALPHA`. The generic controller
supports `srun` and the Yoltla-recommended
`mpiexec.hydra -bootstrap ssh`, explicit multinode placement, concurrent
allocation waves, dependency DAGs, hash-bound artifact transfers, gate tasks,
controlled shutdown, resubmission and read-only progress reporting.

The extension foundation is `Core Contracts 1.0`: versioned validation,
artifact, execution, event, and plugin boundaries with canonical SHA-256
envelopes. This separates future validators, engines, postprocessors, CLIs and
UIs from implementation details and permits gradual migration through explicit
adapters.

The Phase 1 workflow compiler validates typed scientific DAGs, resolves
artifact dependencies, verifies and hashes external inputs, produces
topological plans and graphs, and writes deterministic
`siestaflow.workflow-lock@1.0` envelopes. Compilation never authorizes
execution.

The Phase 2 CLI vertical adds a read-only environment diagnosis, safe and
idempotent project scaffolding from researcher-supplied inputs, and a common
explainable validation report. These commands prepare and diagnose work; they
do not select scientific parameters or authorize execution.

The initial Phase 6 validation foundation adds a versioned SIESTA 5.4.2 rule
catalog, strict researcher-declared context profiles, and hash-bound workflow
preflight. Deterministic input errors can fail; physical and cost heuristics
remain review-only. This layer neither edits inputs nor proves scientific
validity.

The complete local suite passes. Real Yoltla evidence has validated the
allocation-local execution pattern, Hydra runtime, a two-task dependency and
successful reuse of a parent SIESTA density matrix in a package generated by
the 0.2 controller packager. That run also exposed a false negative caused by
checking a mutable restart DM after SIESTA had legitimately replaced it. The
controller now preserves immutable pre-execution transfer evidence and hashes
the final DM independently. Remote confirmation of this correction remains
pending and is not represented as completed acceptance.

Install for development and run the generic example:

```powershell
python -m pip install -e .
python -m siestaflow.cli examples list --json
python -m siestaflow.cli environment check --siesta siesta --launcher auto --json
python -m siestaflow.cli examples validate generic/minimal_siesta_smoke --json
python -m siestaflow.cli examples run generic/minimal_siesta_smoke --campaign-id mesh_series --json
python -m siestaflow.cli campaign progress PATH_TO_PACKAGE --json
python -m siestaflow.cli workflow validate WORKFLOW.json --json
python -m siestaflow.cli input rules --engine-version 5.4.2
python -m siestaflow.cli input validate INPUT.fdf --explain
python -m siestaflow.cli workflow preflight WORKFLOW.json --json
python -m siestaflow.cli workflow plan WORKFLOW.json
python -m siestaflow.cli workflow compile WORKFLOW.json --output workflow.lock.json
python -m siestaflow.cli remote controller-package campaign.json --output packages --json
python -m pytest -q
```
